# Translations (i18n)

LLM Sidebar ships its user interface in several languages. The language follows the browser by
default and can be changed under **Settings → Appearance → Language**.

| Code | Language | Code | Language |
|---|---|---|---|
| `en` | English (fallback) | `nl` | Nederlands |
| `de` | Deutsch (source) | `pl` | Polski |
| `es` | Español | `tr` | Türkçe |
| `fr` | Français | `ru` | Русский |
| `it` | Italiano | `ja` | 日本語 |
| `pt-BR` | Português (Brasil) | `zh-CN` | 简体中文 |

## Where the strings live

```
src/lib/i18n.js            t(), initI18n(), applyI18n(), formatNumber(), formatDate() …
src/lib/languages.js       target languages for translations / video summaries (codes, labels)
src/locales/<code>/
  index.js                 merges the area files below
  common.js                strings shared by several areas            (keys: common.*)
  core.js                  src/lib/* and the background script        (keys: core.*)
  prompts.js               default quick actions, personas, prompts   (keys: prompts.*)
  sidepanel.js             src/sidepanel/*                            (keys: sidepanel.*)
  options.js               options page shell + first sections        (keys: options.*)
  options-sections.js      remaining option sections                  (keys: optionsSections.*)
  content.js               src/content/content.js (toolbar, popover)  (keys: content.*)
  manifest.js              manifest.json strings → _locales/ at build time (keys: manifest.*)
src/locales/all.js         registers every catalog statically (background script only)
```

German (`de`) is the source language and is always bundled, so `t()` works synchronously and in
unit tests without any setup. Lookup order: active language → English → German → the key itself.

## Message format

- Flat keys, namespaced by area: `sidepanel.composer.send`, `options.providers.testConnection`.
- Placeholders in braces: `'Translating to {language} …'` → `t('…', { language })`.
- Plurals: define `key.one` and `key.other` (and `key.few` / `key.many` where the language
  needs them, see `Intl.PluralRules`), call `t('key', { count })`.
- Keep emoji, keyboard shortcuts (`Alt+Shift+L`), product names, `{placeholders}` and Markdown
  unchanged when translating.
- Static HTML uses `data-i18n="key"` (text), `data-i18n-title`, `data-i18n-placeholder`,
  `data-i18n-aria-label`, `data-i18n-alt`; `applyI18n()` fills them in.

## Usage rules for code

- Never evaluate `t()` at module load time (top-level constants): the language is only known after
  `initI18n()`. Use a function or getter instead, e.g. `const labels = () => ({ … t('…') … })`.
- Numbers, dates and currencies: `formatNumber()` / `formatDate()` from `i18n.js`, or
  `Intl.*` with `getLocale()` – never a hard-coded `'de-DE'`.
- Extension pages call `await initI18n(settings.general.language)` before rendering and reload
  when the language setting changes.
- The background script switches language whenever it reads the settings.
- The content script cannot import modules: it receives its strings (`content.*`, `common.*`) in
  the `getContentConfig` response (`config.messages`) and uses its own small `t()`.
- Functions injected with `scripting.executeScript` must stay self-contained (no `t()`).
- LLM prompts are not UI strings: default prompts exist in German and English
  (`prompts.*` keys); German UI → German prompts, every other UI language → English prompts.
  User-edited prompts are never touched.

## Adding a language

1. Copy `src/locales/en/` to `src/locales/<code>/` and translate the values.
2. Add the language to `UI_LANGUAGES` in `src/lib/i18n.js` and to `src/locales/all.js`.
3. `npm test` checks that every catalog has the same keys and placeholders as German.
4. `npm run build` writes `_locales/<code>/messages.json` for the manifest.
